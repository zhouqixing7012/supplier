# 验证码及差旅账单入口技术说明

版本：2026-11-05。

业务规则统一维护在 [需求文档](portal-verification-travel-bill-prd.md)。

## 一、验证码

- 登录邮箱固定验证码仅在测试环境开关开启后使用；获取、发送成功及有效期校验由服务端完成。
- 生产环境默认关闭固定验证码模式；账号密码、账号状态等其他登录条件继续正常校验。

## 二、差旅账单入口

### 当前边界

- 供应商协同门户仅展示差旅系统允许访问的账单类型入口，不选择文件、不上传文件、不在供应商端保存附件。
- 四种入口类型分别为火车、酒店、飞机和租车；可见类型由差旅系统权限返回，上传处理由差旅系统完成。
- 供应商端不设置账期，不增加附件数量、格式或大小限制，不自行展示上传成功或失败结果。
- 旧版供应商端 AJAX 直传、180 秒超时和单附件覆盖方案已由入口跳转方案取代。

### 原型接入点

- 入口权限可由运行容器注入 `window.__PORTAL_TRAVEL_ENTRY_TYPES__`，值为 `train`、`hotel`、`flight`、`rental` 的数组；原型未注入时默认展示四种入口。
- 对应跳转地址可由运行容器注入 `window.__PORTAL_TRAVEL_ENTRY_URLS__`，按上述 key 提供 URL。原型只在地址配置存在且协议为 HTTP/HTTPS 时跳转；未配置时提示入口尚未接入，不模拟上传成功。
- 当前仓库和已检索历史资料未提供差旅系统的四个实际 URL、路由参数或权限接口响应结构，尚不能完成真实系统跳转及权限联调。接入前需取得差旅系统提供的入口映射和权限返回字段。

## 三、历史技术方案

2026-10-15曾记录差旅接口约10秒响应等待阈值、低代码封装服务超时、改用 AJAX 及将等待阈值调整至180秒等方案；同时记录差旅侧单文件覆盖。以上内容属于旧版直传方案的技术背景，现已不适用于供应商端只提供入口的最新规则，保留用于追溯。

## 四、实施与验证状态

- 移动端已调整为四种差旅入口列表，不再显示账期、文件选择、保存草稿和本地上传回执。
- 报价附件已改为多文件列表，支持添加、预览及逐个删除；询价资料和采购订单资料调整到各自明细之前。
- 差旅系统实际 URL、权限接口和真实上传链路尚未接入；本说明不将原型入口视为真实上传完成。
