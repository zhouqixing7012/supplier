# 验证码及差旅账单上传技术说明

版本：2026-11-05。

业务规则统一维护在 [需求文档](portal-verification-travel-bill-prd.md)。

## 一、验证码

- 登录邮箱固定验证码仅在测试环境开关开启后使用；获取、发送成功及有效期校验由服务端完成。
- 生产环境默认关闭固定验证码模式；账号密码、账号状态等其他登录条件继续正常校验。

## 二、差旅账单上传

### 当前页面行为

- 页面固定展示火车、酒店、飞机、租车四类账单；每类使用独立卡片及文件上传入口，不做权限过滤。
- 点击按钮打开当前页面的文件选择器；支持多选，不设置文件格式、大小或数量限制。
- 选择完成后调用对应类型的差旅服务上传适配器，不进行页面跳转。
- 上传中禁用当前类型按钮；成功、失败及超时结果显示在对应账单行内。
- 供应商端不保存账单文件；文件对象仅用于本次请求透传。

### 前端适配器

原型通过 `window.__PORTAL_TRAVEL_UPLOAD__` 接收宿主系统提供的上传函数：

```js
window.__PORTAL_TRAVEL_UPLOAD__ = async ({ type, files, timeoutMs }) => {
  // 宿主系统在此处调用供应商服务，再将附件透传到差旅系统对应入口。
  // type: train | hotel | flight | rental
  // files: File[]
  // timeoutMs: 180000
};
```

- `type` 用于区分火车、酒店、飞机和租车四种差旅服务入口。
- `files` 为本次用户选择的原始 File 对象数组；前端不做格式、大小和数量校验。
- `timeoutMs` 固定传入180000毫秒。适配器应在差旅服务确认成功后 resolve；请求失败、服务返回失败或超时应 reject，前端据此显示服务返回的提示信息。
- 演示原型未配置适配器时，选择文件后完成本地演示并展示上传成功，不发送请求；该分支仅服务于原型演示。已配置适配器时仍按实际回执展示成功或失败，不吞掉服务错误。

### 尚未取得的接口信息

仓库及历史讨论未提供差旅服务的真实接口地址、HTTP方法、multipart字段、四类入口参数映射和响应码规则。因此本次只完成页面上传交互和适配器调用约定，尚未接入真实差旅服务。后续需由接口负责人提供上述契约，再在宿主系统中实现适配器；不在前端猜测接口地址或参数。

### 历史方案

- 2026-10-15已确认上传请求等待时间从10秒调整为180秒，文件采用透传方式，不在供应商系统落库。
- 此前“单附件”“仅支持xls/xlsx”和“多文件只取第一个”的约束已被本次最新需求覆盖，不再作为当前规则。
- 旧版供应商端AJAX直传、低代码封装服务超时问题保留作历史记录；真实接口调用方式仍需按差旅服务当前契约接入。

## 三、实施与验证状态

- 移动端已调整为四类账单各自提供附件上传按钮；文件选择在当前页面完成，不跳转差旅系统。
- 页面支持多文件选择且不设置格式、大小和数量限制；请求通过 `window.__PORTAL_TRAVEL_UPLOAD__` 适配器转交宿主系统。
- 当前尚无真实差旅服务适配器及接口契约，未完成真实文件透传联调。
