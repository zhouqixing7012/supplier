# 验证码及差旅账单优化技术说明

版本：2026-10-15，配套评审稿。

业务规则统一维护在 [需求文档](portal-verification-travel-bill-prd.md)。

## 当前技术现状

以下依据产品本次提供的信息，尚未通过生产代码或接口核实。

- 差旅账单使用透传方式：文件不在供应商系统落库，直接调用差旅服务。
- 原请求等待阈值为 10 秒，差旅接口耗时较长时会超时。
- 低代码平台封装服务的响应阈值不可调整。
- 差旅侧采用覆盖方式仅存储一个文件；供应商侧原支持多文件，但仅取第一个调用服务。

## 改造要求

- 沿用透传方式，账单文件不在供应商系统落库。
- 使用原生 AJAX 替代上述低代码平台封装服务；产品原描述“atjx”按 AJAX 理解，具体实现由研发核对。
- 上传请求超时时间按 PRD 确认值设置；同步检查代理、网关及服务端超时限制，避免仅延长浏览器等待时间但中间链路仍提前断开。
- 请求仅携带本次选择的一个文件，不再采用多文件取首个的逻辑。
- 请求超时不等于差旅处理失败。页面上传状态、成功覆盖及失败保留原附件按 PRD 实现；技术联调需核实差旅侧覆盖结果及超时后能否查询最终处理结果，不以保留原附件的页面状态推断远端文件未变更。
- 登录邮箱固定验证码应结合已有测试环境开关实现，服务端校验逻辑需同步生效，不能只在前端放行。生产默认配置按 PRD 要求核验。
- 固定值的获取动作、发送成功前置条件及有效期限制按 PRD 已确认规则实现。
