# 供应商系统项目知识

供应商系统维护供应商主数据，提供内部员工使用的供应商管理平台和外部供应商使用的协同门户。两端均有 PC 和移动端原型，覆盖邀请、注册、资料维护、审批、评分以及采购协同。[产品范围](../PRODUCT.md) · [原型入口与运行方式](../README.md)

## 按业务查规则

| 业务 | 容易混淆的场景 | 对应章节 |
| --- | --- | --- |
| 供应商查询与我的邀请 | 前者按当前身份、来源、状态和有效标识确定数据范围，后者按当前邀请人归属查询。移动端关键词匹配供应商名称，邀请人使用独立筛选，供应商查询另有证件号码条件。PC 查询字段和导出入口按 PC 覆盖表核对。个人信息的可查询范围与列表、详情的脱敏展示分别校验。 | [权限](supplier-mobile-prd.md#2-权限) · [查询与详情](supplier-mobile-prd.md#41-供应商查询我的邀请与供应商详情) · [PC 覆盖](pc-coverage.md) |
| 删除供应商 | 供应商查询和我的邀请的操作人员、单条入口与批量入口不同。草稿和注册驳回的作废对象及账号影响要分别核对。混选校验、记录作废、账号处理和旧链接行为均按原入口验证。 | [删除供应商](supplier-mobile-prd.md#412-删除供应商) · [历史核对](mobile-prd-open-items.md) |
| 邀请、重新邀请及代注册转邀请 | 普通邀请、本人同名记录命中和从我的邀请直接进入属于不同入口。个人同名可分别受邀。重发邀请沿用原记录，代注册转邀请涉及新邀请创建与原草稿作废，两条路径各有失败保留要求。 | [邀请与重邀](supplier-mobile-prd.md#42-邀请注册与重新邀请) |
| 代注册及受邀登记 | 企业、个人、政府机构或社团、国外供应商的字段和步骤不同。按类型核对国家、证件、注册邮箱、营业执照识别及企业资料回填、名称与证件查重、联系人、银行、资质和预览。普通邀请名称匹配与提交登记查重分别核对。 | [代注册与受邀登记](supplier-mobile-prd.md#43-代注册与受邀资料登记) |
| 修改全部信息、注册驳回和审批 | 注册中继续登记，审批中看只读资料，注册驳回进入修改全部信息。注册驳回重提走注册审批，已生效资料修改走变更审批。整份修改中的明细保存、整体提交和主动放弃影响的范围不同。 | [修改全部信息](supplier-mobile-prd.md#44-修改全部信息) · [门户登录](supplier-mobile-prd.md#491-登录) · [审批结果](supplier-mobile-prd.md#412-审批记录与结果) |
| 修改银行、分配权限、变更邀请人 | 修改银行与分配权限各用独立办理页，单条保存与整单提交审批分开。银行已有记录和本次新增记录的删除规则不同，开户证明单份上传。邀请人交接从两个列表按实际权限办理，单条和批量免审批，批量按整批处理。 | [修改银行](supplier-mobile-prd.md#45-修改银行) · [分配权限](supplier-mobile-prd.md#46-分配权限) · [变更邀请人](supplier-mobile-prd.md#47-变更邀请人) |
| 评分 | 区分从供应商查询发起评分、我的评分待办、已评分修改和只读详情。评分星级、得分、合作信息的读写范围及原记录关联各有规则。PC 供应商评分、评分运维的查询条件按各自入口核对。 | [我的评分](supplier-mobile-prd.md#48-我的评分) · [PC 覆盖](pc-coverage.md) |
| 门户认证与账户 | 注册邮箱用于账号验证，联系人邮箱用于业务联系。供应商自助修改注册邮箱与邀请人通过资料变更修改注册邮箱的验证和生效时点不同。账号、邮箱的空白字符处理与密码规则分别核对。 | [账号和邮箱空格处理](supplier-mobile-prd.md#33-账号和邮箱的空格处理) · [账户维护](supplier-mobile-prd.md#493-账户维护) |

## 原型和设计从哪里开始

| 场景 | 入口与核对点 |
| --- | --- |
| 移动端管理平台 | 站点根路径或 `#/mobile`。先走供应商查询、我的邀请和我的评分。核对搜索、筛选撤销与图标高亮、返回恢复、列表刷新和加载、结果栏吸顶与注册胶囊避让。胶囊左侧代注册为浅蓝，右侧邀请注册使用我的评分选中态的深蓝。左右滑动从列表空白区域发起。 |
| 移动端协同门户 | 管理平台右上角进入门户登录，门户可返回移动端管理平台。核对身份卡、账户、资料查看和编辑、采购任务状态及电脑端差旅提示。采购报价和价税拆分分别检查常规入口及导图直达。 |
| PC 管理平台 | `#/admin/suppliers` 和 `#/admin/invitations`。从列表进入对应供应商与审批。银行信息申请从菜单打开须知弹窗，确认后进入填写页。修改银行、分配权限按独立任务走查。变更邀请人同组对照原、新邀请人。 |
| PC 协同门户 | `#/login`。供应商信息管理从相应资料页签打开修改并进入对应步骤，逐步编辑后预览提交。采购报价、价税拆分和差旅账单从各自菜单进入。 |
| 设计与评审 | 当前规范和可交互组件先看 [DESIGN.md](../DESIGN.md) 与 [移动端组件库](mobile-component-library.md)。`#/mobile/scenes` 用于截图对照。原型评审模式按 [评审模式说明](mobile-review-mode.md) 开启。已部署的原型可以用于走查界面，业务生效仍需相应的服务证据。 |

跨端 UI 复用 ERP 主题、业务表单定义和适用组件。PC 与移动端分别选择适合桌面和触屏的地址、日期、选人、确认与填写交互。表格、标签页、上传控件和固定操作栏的具体约定见[跨端交互组件选型](../DESIGN.md#跨端交互组件选型)。改动视觉时守住原有业务入口、字段和办理结果，涉及页面结构、状态及权限时对照对应 PRD。

## 历史资料和现行口径

| 主题 | 历史材料中的写法或现象 | 目前核对依据 |
| --- | --- | --- |
| 同名重新邀请 | 早期 PC 优化稿写为本人名下【草稿】或【注册驳回】命中。 | 现行移动端 PRD 4.2 对非个人同名匹配写为【邀请中】或【草稿】。注册驳回重提见 4.4。涉及 PC 同名入口的上线范围时应按端核对。 |
| 搜索与导出 | 早期问题稿记录移动端按邀请人搜索与导出不便，也提出过导出范围优化。 | 现行移动规则将关键词与邀请人筛选分开。移动业务列表导出下线记录见 [评审核对](mobile-prd-open-items.md)，PC 导出见 [PC 覆盖](pc-coverage.md)，原型导图导出属于评审工具。 |
| 银行资料暂存 | 早期反馈重点是保存账户后遗漏提交。 | 独立修改银行保留已保存待提交内容，整份资料修改按放弃时的恢复规则处理。两种流程分别按 [4.5](supplier-mobile-prd.md#45-修改银行) 和 [4.4](supplier-mobile-prd.md#44-修改全部信息) 核对。 |
| 审批通知与授权建议 | 初版材料曾列服务号审批结束通知、撰稿人新增授权。 | 这两项后续移出本轮优化，现行 [4.12](supplier-mobile-prd.md#412-审批记录与结果) 单独定义注册审批最终结果邮件。当前已有角色的查询范围见 [2.2](supplier-mobile-prd.md#22-数据权限)。 |
| 采购和评分日期筛选 | 早期移动走查记录了采购日期两行、我的评分及运维错误定位差异、明细表单布局混用和导图直达标题偏差。 | 日期外观统一后的业务含义见 [3.2](supplier-mobile-prd.md#32-查询选择和提交) 与 [4.10.1](supplier-mobile-prd.md#4101-任务查询)，历史修订和覆盖见 [上下文](../CONTEXT.md) 与 [移动交互复核](mobile-ux-followup.md)。 |
| 移动视觉讨论 | 注册栏对等权重、列表卡片分隔线、采购表单提示等曾有方案讨论。 | 采用 [设计规范](../DESIGN.md#移动端卡片分隔与字段样式) 的当前方案。讨论稿和对照图供追溯。 |

前期材料包括《供应商协同门户移动端 (2)》《供应商系统问题修复与优化PRD》《供应商系统优化PRD(2)》及《供应商移动端UI交互一致性排查报告》。前两份适合追溯问题和初版方案，优化 PRD 是随后整理的需求稿，UI 排查报告记录了特定历史提交的实测范围。仓库内可从[历史需求](mobile-prd.md)、[历史走查](mobile-ui-audit-2026-11-05.md)和[后续复核记录](mobile-ux-followup.md)开始找对应主题。
