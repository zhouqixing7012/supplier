# PC 原型页面覆盖

核对范围为 feat/mobile-change-comparison 的 [现系统前端代码导出目录](../供应商前端代码)、2026-11-11 补充的两端菜单及审批页面截图，以及已确认需求。导出为低代码单页配置，包含字段、明细和页面脚本。PC 原型用 ERP 主题、Card、QueryBar、DetailGrid、PcTable 及 PcModal 实现页面。

## 仍需现系统资料

1. **PC 角色及列表配置**。按角色的菜单可见范围，我的邀请、待审批和已审批任务、评分、黑名单、银行申请、报价及价税拆分列表的字段和筛选条件。
2. **审批节点、选择器及动作**。付款公司选择器截图或配置，领导、财务及资料变更节点的可编辑字段，以及加签、延期的操作弹窗和处理规则。当前注册业务审批用演示付款公司候选，演示办理结果只更新当前审批任务。
3. **手动同步及黑名单管理**。同步对象、触发方式及回执，黑名单拉黑及移除权限和生效条件。
4. **首次邀请注册与服务联调**。邀请链接参数及首次注册入口的脱敏示例，付款公司、业务实体及部门字典，差旅账单模板和四类服务回执示例。

原型内的本地演示记录不表示已完成正式认证、审批、邮件发送或文件上传。差旅未注入宿主上传服务时显示未接入。

两列表的跨端查询范围见[数据权限](supplier-mobile-prd.md#22-数据权限)，操作条件见[操作权限](supplier-mobile-prd.md#23-操作权限)。各角色演示地址见[API 与 Mock](mobile-api.md#演示能力)。邀请编号、办理结果、评分和权限待提交资料保存在当前浏览器标签页会话。实际邀请邮件、注册链接、账号失效和跨员工数据同步需正式服务。

## PC 门户资料编辑的验收差异

- PC 门户已具备三个资料页签、按来源分组进入编辑步骤、步骤条及预览提交。界面要求见[资料修改设计](../DESIGN.md#资料修改与附件显示补充)。
- 静态核对发现，[PC 资料编辑组件](../src/pc/record-editor.jsx)的推进按钮只展示「下一步」。按设计验收时需检查步数文案，以及从各起始分组进入并切换上一步后的步数。本项未运行浏览器。
