# 新媒体版权供应商统一管理及查询接口 PRD

## 1. 需求背景

此前新媒体版权业务自行维护供应商信息。后续新媒体版权供应商统一纳入供应商管理平台，由供应商管理平台维护供应商主数据及新媒体版权业务权限。新媒体版权系统通过接口查询符合业务权限的供应商，使用统一的供应商资料。

## 2. 需求范围

1. 供应商主数据统一在供应商管理平台维护。
2. 供应商管理平台在现有【分配权限】功能中新增【新媒体版权】所属权限，权限分类为【免费类】和【采购类】。供应商满足现有分配权限办理条件时，可在该功能中新增、修改或删除对应权限记录；权限保存、重复校验、提交审批及审批生效按供应商管理平台现行分配权限流程执行。
3. 新媒体版权系统调用供应商查询接口，按供应商名称、所属业务和业务分类查询供应商列表。

## 3. 新媒体版权权限

| 字段 | 取值 |
| --- | --- |
| 所属权限 | 新媒体版权 |
| 权限分类 | 免费类、采购类 |

供应商通过供应商管理平台现有【分配权限】功能维护新媒体版权权限。新增、修改或删除权限提交审批后，审批通过才更新正式权限；待审批或已驳回的变更不作为已生效权限提供给新媒体版权系统。

## 4. 供应商查询接口

### 4.1 接口信息

| 项目 | 内容 |
| --- | --- |
| 接口名称 | 按供应商业务查询供应商列表 |
| 调用系统 | 新媒体版权系统 |
| 接口地址 | `{SUPPLIER_URL}/api/supplier/supplierInfoBySupplierBusiness{SUPPLIER_URL_PARAM}` |
| 接口用途 | 按供应商名称、所属业务及业务分类查询供应商列表 |
| 请求方式 | 待接口双方确认 |

### 4.2 查询条件

| 查询字段 | 建议参数名 | 是否必填 | 取值及匹配规则 |
| --- | --- | --- | --- |
| 供应商名称 | supplierName | 否 | 支持按供应商名称模糊匹配 |
| 所属业务 | supplierBusiness | 是 | 固定传入【新媒体版权】 |
| 业务分类 | businessCategory | 否 | 【免费类】、【采购类】 |

**多条件筛选规则**

1. 【所属业务】为必传条件，未传或为空时，接口按参数校验失败处理。
2. 【供应商名称】和【业务分类】为选传条件。未传时不增加对应筛选限制。
3. 【供应商名称】按模糊匹配筛选。
4. 多个已传条件按交集筛选，即供应商须同时满足所有已传条件。
5. 未传【业务分类】时，查询该供应商已生效的全部新媒体版权业务分类；未传【供应商名称】时，不限制供应商名称。

### 4.3 查询范围与结果

1. 供应商资料以供应商管理平台当前正式生效的资料为准。
2. 查询结果须匹配供应商已生效的【新媒体版权】权限及传入的业务分类。
3. 尚未审批通过的新增或修改权限不纳入查询结果；权限变更审批驳回时，继续按原正式权限查询。
4. 已拉黑的供应商不纳入查询结果，即使其已生效的新媒体版权权限符合查询条件，也须从结果中剔除。
5. 接口返回符合查询条件的供应商列表。无匹配供应商时的响应结构及提示方式待接口双方确认。

### 4.4 返回数据

接口返回的供应商业务字段限定为以下四项：

| 返回字段 | 说明 |
| --- | --- |
| 供应商唯一标识 | 供应商在供应商管理平台的唯一标识 |
| 供应商名称 | 供应商正式名称 |
| 所属业务 | 本次命中的所属业务，固定为【新媒体版权】 |
| 业务分类 | 本次命中的已生效业务分类，为【免费类】或【采购类】 |

## 5. 当前尚未定义

| 编号 | 待确认问题 | 涉及内容 | 建议及影响 |
| --- | --- | --- | --- |
| Q1 | 接口请求方式、认证方式及调用方身份如何确定？ | 接口接入 | 建议采用系统间身份认证，并限定新媒体版权系统调用；具体认证方式需结合现有网关确定。 |
| Q2 | 接口是否需要分页及排序？ | 返回结果 | 根据新媒体版权系统的列表展示和数据量确定，影响请求参数及响应结构。 |
| Q3 | 无匹配数据、参数错误及系统异常时，接口采用什么响应结构和错误码？ | 接口响应 | 与现有接口规范统一，便于调用方区分无数据、参数错误和服务异常。 |
| Q4 | 除已拉黑供应商外，已停用供应商是否也需要从查询结果中排除？ | 查询范围 | 本需求已明确排除已拉黑供应商；其他状态的排除范围仍需确认，避免扩大过滤条件。 |
| Q5 | 原新媒体版权系统中的供应商是否需要批量迁移至供应商管理平台？迁移哪些资料，如何匹配已有供应商并处理重复记录？ | 历史供应商纳入 | 需确认迁移范围、数据来源、匹配依据及重复数据处理方式，避免重复创建供应商主数据。 |
| Q6 | 所属业务、业务分类的接口传值使用中文名称还是字典编码？ | 请求参数 | 需与接口双方统一参数取值，避免调用方传值与供应商管理平台字典不一致。 |
| Q7 | 同一供应商同时拥有【免费类】和【采购类】两项已生效权限时，接口按业务分类分别返回两条记录，还是合并为一条记录？ | 返回结果 | 建议按供应商与业务分类的匹配结果分别返回，避免丢失分类信息；最终返回粒度需由双方确认。 |
