## 核对范围

基于 main 提交 `06068ed32f45e80ccad07cb3f3799c91866f1640`，逐项阅读移动端业务 PRD、原型说明、页面范围清单及管理平台/协同门户/邀请注册相关实现。此次仅调整文档，未修改原型代码；核对方式为源码与文档静态对照，未执行浏览器交互、真机或真实业务提交验证。

业务规则以 [移动端 PRD](mobile-prd.md) 为准。本文记录核对证据、当前差异及文档修订范围，供评审定位。

## 原型仍需核对的差异

这些差异未通过改写需求消除，避免把当前演示行为直接认定为已确认业务规则。

|项目|当前实现证据|PRD口径及后续处理|
|---|---|---|
|差旅权限缺省|`src/pages/mobile-portal.jsx`：权限值不是数组时回退展示全部四类入口；没有独立权限加载失败和重试状态|按差旅系统授权展示入口；空权限与加载错误分别反馈。需补权限加载分支后验收|
|个人证件起始日期|`src/pages/mobile-forms.jsx` 的个人字段将起始日期统一必填；`src/pages/mobile-supplier.jsx` 按该配置执行下一步校验|PRD保留港澳通行证等起始日期可选的既有要求；其他证件适用范围待确认，再统一字段配置及校验|
|个人门户联系人|`src/pages/mobile-portal.jsx` 固定展示基本信息、联系人信息、银行信息三个分组；注册流程已按个人类型跳过联系人|个人注册跳过联系人已明确；个人登录后门户联系人分组显隐需确认后统一。当前门户演示主体是企业，不能据此证明个人路径已通过|
|邀请人变更|`src/pages/mobile-supplier.jsx`：单条按演示发起人分流状态，批量直接替换邀请人且未进入相同审批分流|PRD保留单条页面审批提醒，批量审批、生效时点及混合批次处理列为待确认；确认后统一单条与批量结果|
|评分总分|`src/pages/mobile-workflows.jsx` 保存新评分时将score设为空，历史样例包含已有总分|保留原始分值平均算法，星级到原始分值映射待确认；本次未据样例分数反推或给新评分补造总分|
|银行信息申请结果|`src/pages/mobile-workflows.jsx` 的结果为申请信息暂存摘要|PRD区分填写结果、审批结果及目录生效；正式单号、审批及目录生效待确认|
|已审批资料修改的草稿|`src/pages/mobile-supplier.jsx` 底部在修改全部信息模式隐藏保存草稿；代注册及邀请注册提供保存草稿|本次保留当前范围：修改全部信息按变更提交；原有草稿能力对应代注册及邀请注册|

## 待确认的业务决定

统一收录在 PRD 末尾“待确认业务规则”，包括评分映射及修改权限、批量评分、银行申请结果、特殊财税校验、资料字段边界、邀请和账户策略、邀请人变更审批、注册/资料审批、文件导出及上线公告。文档未把真实服务接入事项累计为新的业务页面，也未因存在后端接口新增菜单。
